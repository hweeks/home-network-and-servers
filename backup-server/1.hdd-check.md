# disk burn‑in and prep on Ubuntu Server

this guide walks through a burn‑in process for new HDDs before creating a ZFS `RAID‑Z1` pool. it uses SMART for diagnostics and a full surface write/read test to catch early failures.

## overview

we need to verify each HDD is healthy before use. we will use

1. SMART short/extended
2. surface test with badblocks (destructive; wipes disks)

> note: estimated time per 20TB drive
>
> - SMART extended: _~12–30+ hours_
> - surface test: _~24–36 hours_ (can run drives in parallel)

## prerequisites

install tools

```bash
sudo apt update
sudo apt install -y smartmontools
# badblocks is usually present via e2fsprogs; install if missing:
sudo apt install -y e2fsprogs
```

## identify the disks

list disks and models

```bash
ls -l /dev/disk/by-id/
# should output entries like:
# - `/dev/disk/by-id/ata-...` → HDDs
# - `/dev/disk/by-id/nvme-...` → NVMe drives
```

write down all HDD by‑id paths. for example, `/dev/disk/by-id/ata-HDD_n`

## enable and check SMART

SMART should already be on but check it just in case with

```bash
sudo smartctl -s on /dev/disk/by-id/ata-HDD_n
```

run a quick health readout

```bash
sudo smartctl -a /dev/disk/by-id/ata-HDD_n
```

repeat for each HDD.

look for:

- `Reallocated_Sector_Ct` = **0**
- `Current_Pending_Sector` = **0**
- `Offline_Uncorrectable` = **0**

## run SMART extended test

we can run the long SMART test with

```bash
export LC_ALL=C;

# replace ata-HDD_n with your /dev/disk/by-id path.
sudo smartctl -t long "/dev/disk/by-id/ata-HDD_n"
```

progress can be checked manually

```bash
sudo smartctl -c /dev/disk/by-id/ata-HDD_n
```

confirm key attributes remain 0

```bash
sudo smartctl -a /dev/disk/by-id/ata-HDD_n
```

check `Reallocated_Sector_Ct`, `Current_Pending_Sector`, `Offline_Uncorrectable`, `Reported_Uncorrect`.

## run surface write/read test

this nukes the data on the disk.

```bash
# replace ata-HDD_n with your /dev/disk/by-id path.
# destructive surface test: writes patterns and verifies (erases the disk)
# runs detached and logs to a file; check logs manually
# note: for 18–20TB disks, add a larger badblocks block size to
# keep total blocks under 2^32; use -b 8192

DEV=/dev/disk/by-id/ata-HDD_n
LOG=bb-HDD_n.log
nohup sudo badblocks -wsv -b 8192 -t 0x00 -p 1 -o "$LOG" "$DEV" \
  >"/tmp/${LOG%.log}.out" 2>&1 &
echo "started badblocks for $DEV (log: $LOG; out: /tmp/${LOG%.log}.out)"
```

manual checks:

- tail output: `tail -f /tmp/bb-HDD_n.out`
- view badblocks log: `sed -n '1,200p' bb-HDD_n.log`
- list running jobs: `ps -o pid,etimes,cmd -C badblocks`

to schedule multiple disks at once, start one per device (parallel):

```bash
for DEV in \
  /dev/disk/by-id/ata-HDD_1 \
  /dev/disk/by-id/ata-HDD_2 \
  /dev/disk/by-id/ata-HDD_3
do
  NAME=$(basename "$DEV")
  LOG="bb-${NAME}.log"
  nohup sudo badblocks -wsv -b 8192 -t 0x00 -p 1 -o "$LOG" "$DEV" \
    >"/tmp/${LOG%.log}.out" 2>&1 &
  echo "started: $DEV (log: $LOG)"
done
```

## recheck SMART after surface test

```bash
sudo smartctl -a /dev/disk/by-id/ata-HDD_n
```

confirm again:

- `Reallocated_Sector_Ct` = 0
- `Current_Pending_Sector` = 0
- `Offline_Uncorrectable` = 0
- no errors in SMART self‑test log

if badblocks reports errors or SMART shows any of the above non‑zero, replace the drive.
